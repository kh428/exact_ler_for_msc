# How to follow the additional calculations

The short path through the code is:

1. `alternatives/results.py` reads the fractions and divides or evaluates series.
2. `alternatives/verification.py` reconstructs coefficients and checks the saved
   batch sums, counts and physical-location corrections.
3. `alternatives/recompute.py` runs the native calculations explicitly selected
   on the command line.
4. `alternatives/calculation/` contains the circuit tensors and C++ arithmetic.

Verification needs only the standard library. Recomputing uses NumPy and a
C++17 compiler. Plotting uses NumPy and Matplotlib. ZX evaluation has its own
pinned dependencies, including the parametrised PyZX fork.

## d=3: polynomial tensor contraction

Each noise location contributes `1 + x × fault_law` after removing `(1-p)^N`.
The circuit compiler retains measurement records, signed Pauli coefficients
and post-selection constraints. It never treats a signed term as a probability.
The saved contraction order sums all internal indices and all slice assignments.

Arithmetic takes place modulo a certified prime, with either embedding of
√2. The verifier combines both embeddings, reconstructs the rational and √2
parts separately, and proves the latter vanish. The raw coefficients are bounded
before division by the acceptance series. Sufficient denominator factors are:

| Case | Denominator dividing each raw degree-k coefficient | Locations |
|---|---|---:|
| RP² d=3 | 2^79 × 15^k | 678 |
| Fold d=3 | 2^83 × 315^k | 374 |
| Chan v1 d=3 | 2^54 × 15^k | 658 |

Multiplying these denominators by `binomial(N,k)` gives the numerator height
used in reconstruction. Three primes exceed twice the required signed bound.
Chan d=3 also has three unused primes for an independent arithmetic check.

`recompute_other.py polynomial` rebuilds the network from the frozen gate/noise
model and compares all its residues for the selected prime and embedding.
It reuses the saved contraction order when its index labels match. The Chan
adapter can introduce different auxiliary XOR labels; in that case it chooses
a new order for the compiled network. Neither route uses stored answers to
perform the contraction. The command does not regenerate the frozen model
from an upstream circuit generator.

## RP² and Fold d=5: exact phase responses and class sums

The successful d=5 implementation differs from the d=3 polynomial tensor
contraction. It first eliminates linear constraints and compiles an exact
quadratic phase response for an error label. Faults with the same response
label are grouped, then compatible classes are summed. Corrections from
physical-channel power sums exclude repeated fault locations.

The phase inputs contain labels, compatibility signatures and the first four
channel power sums. The C++ kernel evaluates the signed quantum sum exactly
before taking its probability. Integer-height bounds cover the signed
128-bit accumulators. No Monte Carlo sampling enters these coefficients.

The complete ledgers contain 17,306 RP² sixth-order batches and 23,542 updated
Fold sixth-order batches. Fold also includes the 23,543 fifth-order batches
needed for its lower-class correction terms. Gzip changes only storage:
every record and its original checksum is retained.

`verify_other.py` streams these records, checks every batch hash and task,
matches the independent class census, sums exact fractions, restores the
physical-location corrections, then divides by the required acceptance series.
It verifies the recorded calculation rather than independently resimulating
the circuit. The model-to-phase compilation is not regenerated by this command.

`recompute_other.py batch` compiles the C++ kernel and repeats one complete
batch from the frozen phase input. The same interface can repeat other batches
by identifier. Full campaigns took 12.75 and 26.36 core-hours, respectively;
they are not launched by the package's quick checks. A new full campaign
controller and regeneration of the phase inputs are outside this small release.

## Chan d=5

For arXiv v1, the supplied records certify every raw coefficient through degree
seven using the bound `2^38 × 15^k × binomial(2308,k)` and three primes.
`verify_other.py` reconstructs both raw series before calculating their quotient.

For the four-round source, the degree-six calculation splits by growth weight.
Growth orders zero to three are contracted against the polynomial endpoints.
The remaining contributions are `G4 h1` at degree five, and `G4 h2 + G5 h1`
at degree six, with `h1=W0 F_B1` and `h2=W0 F_B2 + W1 F_B1`. The noiseless
final accepted-error response vanishes, so higher growth weights do not
contribute through degree six.

The package includes the sparse exact endpoint functions, growth channels,
partial reconstruction residues, two reconstruction primes, a held-out prime,
integer bounds and the v1 regression. `recompute_other.py chan-growth` rebuilds
the physical growth power sums and repeats all G4/G5 terms. It deliberately
reuses h1/h2 and the certified lower-growth endpoint contribution. It is not a
from-scratch reconstruction of all earlier stages or an all-orders LER.

## Scope of the refactor

The public entry points take explicit inputs or use package-relative data.
They write only to a new output directory. The code does not import a sibling
research checkout, depend on a prebuilt native library, or run at import time.
No full coefficient campaign is hidden behind a verification or plotting command.

The original arithmetic bodies and native kernels are retained where possible.
Keeping those bodies stable makes the saved-record regression meaningful and
avoids mixing a scientific change with packaging. Large scratch arrays, job
supervisors and abandoned representation searches are not distributed.
